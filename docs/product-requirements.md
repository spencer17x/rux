# Rux v1 产品基线：ChatGPT Codex 功能一致

更新时间：2026-08-19

## 1. 唯一产品目标

Rux v1 是当前 ChatGPT 桌面客户端中 Codex 工作区的功能一致实现，使用 `Rux` 作为产品名称。

第一版不再定义独立于 ChatGPT Codex 的产品路线。Rux 不新增自有 Agent、Provider 编排、模型路由、项目管理、自进化、同步协议或其他差异化功能。只要目标客户端没有对应的用户入口、状态或行为，Rux v1 就不得暴露。

“功能一致”同时包括：

- 相同的用户任务和入口；
- 相同的信息架构、默认状态与逐步披露；
- 相同的关键交互、键盘路径、加载、失败与恢复行为；
- 相同的可见功能边界；
- 相同的本地 Codex Session 连续性、审批和 Changes 证据语义；
- 在同平台、同账户能力和同窗口状态下，视觉层级与密度足够接近，不能出现 Rux 自创界面。

品牌替换和更严格但不可见的安全实现不算产品差异。

## 2. 基线证据优先级

出现冲突时按以下顺序决定 v1 行为：

1. 用户指定或提供的当前 ChatGPT Codex 客户端画面、可操作路径和直接反馈；
2. 同一目标版本、平台、账户能力和地区下新捕获的客户端证据；
3. 当前 OpenAI 官方文档与发布说明；
4. 官方 Codex App Server/CLI 暴露的稳定能力；
5. 仓库现有实现只作为迁移材料，不作为产品需求来源。

不得用 CLI、App Server、实验标志或历史 Rux 能力推导一个目标客户端没有显示的产品入口。官方文档描述的账户、地区或策略限定能力，只有在参考客户端实际可见时才进入该基线。

每次发布验收必须记录：

- ChatGPT 客户端版本；
- 平台与逻辑视口；
- 账户/地区相关功能门控；
- 对照截图和完整点击路径；
- 无法直接验证的项目。

## 3. 已确认的当前基线事实

2026-08-19 用户提供的 2866 × 1624 当前客户端截图是本轮最高优先级证据，保存在 `design-audit/chatgpt-codex-current-2026-08-19/`。

- 当前 ChatGPT Codex Composer 显示模型与推理强度选择，例如 `5.6 Sol 中`。Rux 保留模型选择并按该控件的内容、位置和状态对齐。
- 模型控件在用户打开时必须加载真实 Codex 目录，显示可区分的模型和推理强度，并在选择后更新当前 Task；只显示当前模型不算完成。
- 模型入口使用当前 Codex 的分层菜单：一级为模型、推理强度、速度和高级，模型/推理/速度各自在右侧子菜单选择；不得再展示单个扁平滚动模型列表。速度使用 `model/list` 的 `serviceTiers/defaultServiceTier`，并把非默认 tier 作为 `serviceTier` 传给官方 App Server。
- Composer 支持直接粘贴剪贴板图片，显示可移除预览，并通过官方 App Server `localImage` 输入随当前 Run 发送。
- 左侧一级导航为 `新对话`、`拉取请求`、`站点`、`已安排`、`插件`，之后才是项目与任务历史。
- 底部账户行打开锚定在侧栏底部的账户菜单，包含使用情况、邀请好友、设置和退出登录；Rux v1 不显示宠物入口或宠物设置分类。
- 账户行显示可验证的 ChatGPT 连接身份；不得把“账户与登录”当作用户名，也不得显示硬编码的剩余用量。菜单必须完整显示首行身份和末行登录/退出操作，不得因固定高度与按钮尺寸冲突而裁切。
- 账户菜单提供“一键同步 ChatGPT”。只有用户点击时才通过官方 App Server `account/read` 与 `account/rateLimits/read` 读取账户邮箱、套餐和限额窗口；结果只保留在当前内存 UI，不持久化邮箱，不读取或暴露 Token，也不后台自动刷新。
- 外部 Agent 会话导入只有“导入到 Rux”一种正常路径：复制规范化历史和来源证据，创建可编辑的 Rux Task；首次继续时创建 Rux 管理的新 Native Session，并以有界历史作为上下文。不得恢复或写入来源 Session，也不得因来源 Session 不可用、解除关联或历史 `view` 状态锁定 Composer/模型选择。
- 设置采用全高两栏结构，当前截图确认个人、集成与编码分类，以及常规页中的权限、文件打开目标、语言、菜单栏、底部面板、终端位置、防止休眠和速度设置。
- 顶部快捷工具菜单包含审阅、终端、浏览器、文件和侧边聊天；Terminal 以底部可调整面板打开。
- 审阅、Terminal 和右侧 Environment 使用与当前客户端一致的停靠关系：Terminal 与右侧面板互斥；Terminal 的新增、切换和关闭标签必须真实工作。
- 右侧环境信息面板显示变更、本地、分支、提交或推送、比较分支和来源。
- 新对话直接进入空白任务，不先经过 Rux 自定义设置向导。
- 新对话立即使用最近一次校验通过的官方模型目录快照，并由该次用户操作主动刷新目录；不得把 Engine 默认占位显示为 `Codex 中`。首次目录尚未返回时显示加载或选择状态，返回后显示真实默认模型及推理强度。
- 项目、任务历史、单一任务正文、底部 Composer、审批、Changes、环境和 Terminal 按目标客户端的当前行为实现。
- 账户与项目切换保持独立；认证与原生 Session 由官方 Codex 边界持有。

这些事实可被更新的同版本客户端证据纠正，但不能被仓库历史实现覆盖。

## 4. 功能一致性矩阵

下表是验收索引，不是 Rux 自定义路线图。`目标客户端可见` 的能力必须完整实现；`目标客户端不可见` 的能力必须从 v1 UI 移除；尚未取得同版本证据的能力标记为 `待核对`，不得用模拟入口冒充完成。

| 表面 | 必须核对的行为 | v1 规则 |
| --- | --- | --- |
| 启动与认证 | 首次启动、登录、退出、未安装/未连接、错误恢复 | 与当前 Codex 一致；只使用官方 Codex 认证边界 |
| 项目与任务 | 打开项目、项目分组、新建、搜索、置顶、归档、恢复、任务切换 | 可见结构、排序、状态与快捷操作一致 |
| Composer | 文件/更多、权限、模型/推理强度、语音、发送、停止、排队、快捷键 | 控件集合、顺序和状态与目标一致 |
| Transcript | 用户/助手消息、计划、工具活动、折叠、错误、反馈、回到最新 | 内容顺序、状态和默认展开策略一致 |
| 审批 | 命令、文件、网络、工具请求以及批准/拒绝/停止 | 只在具体动作发生时请求，范围和恢复一致 |
| Changes/Review | 工作区变化、Run 归属、diff、文件/块操作、评论、撤销/恢复 | 以目标客户端实际提供的粒度为准 |
| Environment | Local、Worktree、Cloud、Remote、来源、分支和环境状态 | 只实现参考客户端可见的模式与切换路径 |
| Terminal | 打开、关闭、后台进程、重启恢复和工作区隔离 | 行为与非恢复默认值一致 |
| 长任务 | 目标、后台运行、通知、计划任务与结果入口 | 按参考账户实际可见能力完整实现或完全隐藏 |
| 工具与扩展 | Skills、Plugins、Apps、Browser、Computer Use、Web、图片与文件 | 只有参考 Codex 表面可见的入口进入 v1 |
| 设置 | 常规、权限、个性化、通知、环境、工具和账户 | 分类、默认值、禁用状态与目标一致 |
| Session 连续性 | 新建、恢复、重连、失败、归档、删除、分叉或交接 | 使用官方 Session 身份；不把新 Session 冒充恢复成功 |
| 可访问性 | accessible name、键盘、焦点、缩放、对比度、状态通知 | 关键路径与目标至少等价，不能因复刻降低可用性 |

## 5. 明确删除的旧需求

以下内容不再是 Rux v1 需求，也不得因仓库仍有兼容代码而恢复入口：

- 多 Agent 工作台与 Agent Builder；
- Claude Code、Rux Native 或自定义 Provider 作为 Rux 自有选择；
- Agent Revision、跨 Agent Handoff 和 Auto 模型路由的产品 UI；
- Rux Project Board、需求看板和 Improvement Center；
- 受控自进化、隔离 A/B 评测和 Rux-managed 资产发布；
- Rux 自定义云同步、遥测成功仪表盘和独立账户体系；
- 与目标 ChatGPT Codex 不一致的 TUI 产品路线；
- 任何仅因为历史代码已经实现而保留的导航、设置或创建流程。

如果未来 ChatGPT Codex 在目标客户端正式提供同名或等价能力，应按新的客户端证据重新加入 parity 矩阵，而不是复活旧 Rux 设计。

## 6. 数据和兼容代码

旧实现和历史本地数据可以暂时保留，以避免无授权的数据破坏，但必须满足：

- 正常 v1 启动、新建、设置和任务操作不会创建新的旧产品对象；
- Renderer 不显示旧功能入口；
- 不在后台联系非 Codex Provider；
- 不把兼容字段、内部模型 ID 或迁移状态暴露为产品概念；
- 删除代码或数据前另做影响预览和迁移，不在本次需求重置中静默清理用户数据。

保留兼容实现只是一项工程债务，不代表 v1 范围。

## 7. 完成标准

Rux v1 只有同时满足以下条件才可称为“与 ChatGPT Codex 功能一致”：

1. parity 矩阵中所有目标客户端可见路径均有真实实现，不使用展示数据冒充；
2. 所有目标客户端不可见的旧 Rux 入口均已移除；
3. 同版本、同平台、同账户能力、同视口的关键路径已经逐屏对照；
4. 新建任务、真实 Codex Run、具体审批、Changes 审查、Terminal、重启恢复和项目切换均通过实际打包应用；
5. 产品、可访问性、协议、Runtime、安全、构建和打包门禁全部通过；
6. 所有无法验证的差异均明确列出，不使用“完全一致”措辞掩盖证据缺口。

## 8. 当前实现状态

当前仓库尚未达到本合同。它已有可运行的 Codex 本地主链、模型选择和严格的进程/凭据边界，但主导航、账户菜单、设置分类、快捷工具与底部面板仍需按当前截图统一。后续工作必须按本文件逐项消除差异；旧路线图和阶段编号不再有效。
